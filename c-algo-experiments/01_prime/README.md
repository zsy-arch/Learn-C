# 01_prime —— 素数判断与筛法

## 实验目的

回答一个具体问题：**教科书说的「试除到 sqrt(n)」优化，到底快多少？**

不看理论，直接测。同时对比第三种做法 —— 埃拉托斯特尼筛法。

## 三种算法

| 算法 | 时间 | 空间 | 适用场景 |
|---|---|---|---|
| 朴素试除（试到 n-1） | O(n) | O(1) | 只适合教学 |
| 试除到 √n | O(√n) | O(1) | **判断单个数** |
| 埃氏筛 | O(n log log n) | **O(n)** | **枚举一批素数** |

## 机制剖析

### 为什么能只试到 √n

如果 `n = a × b` 且 `a ≤ b`，那么一定有 `a ≤ √n`。
所以只要试到 `√n` 都没找到因子，n 就一定是素数。

```text
n = 36 = 1×36 = 2×18 = 3×12 = 4×9 = 6×6
                                    ↑
                            因子对的分界点在 √36 = 6
                            6 之后的因子对都是前面出现过的（只是顺序反了）
```

### `d * d <= n` 的溢出陷阱

```c
for (unsigned d = 3; d * d <= n; d += 2)       /* ⚠️ n 接近 UINT_MAX 时 d*d 会溢出 */
for (unsigned d = 3; d <= n / d; d += 2)       /* ✅ 除法版本，永远安全 */
```

两种写法在本实验的 n 范围内结果完全一样（`0.412 ms` vs `0.423 ms`），
但 `d * d` 在 `n > 65535²` 时会回绕，导致判定错误。**生产代码用 `n / d`**。

### 筛法的空间代价

```text
========== 8. 筛法的空间代价 ==========
  sizeof table for 1e6   = 1000001 字节 (unsigned char)
  如果用 bool[] (1 字节) = 1000001 字节
  如果用位图（1 bit/数） = 125000 字节  <- 8 倍压缩
  如果用 int[] (4 字节)  = 4000004 字节  <- 别这么干
```

## 两个易错点

```c
/* ❌ 忘记处理 0 和 1 —— 它们都不是素数 */
if (n % 2 == 0) return n == 2;    /* 这个写法是对的，但别忘了前面的 n < 2 */

/* ❌ 忘记特判 2 */
for (unsigned d = 3; d <= n/d; d += 2)   /* d 从 3 开始，跳过了所有偶数 */
    ...
/* 如果不特判 n == 2，2 会被判成非素数 */
```

实测验证：

```text
  is_prime_sqrt(0)  = 0
  is_prime_sqrt(1)  = 0
  is_prime_sqrt(2)  = 1  <- 特判生效
```

## 最佳实践

1. **判断单个数**用试除到 `√n`，写法是 `d <= n / d`（不用 `d*d`，不用 `sqrt()`）。
2. **枚举一批数**用筛法，但要意识到 O(n) 的内存代价。
3. 素数判断一定要先处理 `n < 2`、`n == 2` 这两个边界。
4. 筛法的 `calloc` 会自动清零，比自己 `memset` 更清晰。
5. 从 `p*p` 开始标记，而不是从 `2*p` —— 更小的倍数已经被更小的素数标过了。
