# 02_fibonacci —— 四种实现与调用次数实测

## 实验目的

回答一个具体问题：**`fib(40)` 的朴素递归到底调用了多少次函数？**

不猜，直接数。然后用四种实现对比，看清「重复计算」的代价。

## 文件

| 文件 | 作用 |
|---|---|
| `demo.c` | 四种实现 + 调用计数 + 溢出边界 |

## 编译与运行

```bash
cc -std=c17 -Wall -Wextra -Wpedantic -Werror -O0 -g demo.c -o demo
./demo
```

## 四种实现

| 实现 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 朴素递归 | **O(1.618ⁿ)** | O(n) 栈 | 只适合教学 |
| 记忆化（自顶向下） | O(n) | O(n) | 好写，但要处理「未计算」标记 |
| 迭代（自底向上） | O(n) | **O(1)** | **首选** |
| 矩阵快速幂 | **O(log n)** | O(1) | n 极大时才有意义 |

## 机制剖析

### 递归树：重复计算从哪来

```text
                    fib(5)
                   /      \
              fib(4)        fib(3)      ← fib(3) 算了两遍
             /     \       /     \
        fib(3)   fib(2)  fib(2)  fib(1)  ← fib(2) 算了三遍
        /    \    /   \   /   \
    fib(2) fib(1) ...
      ...
```

`fib(n)` 的递归树是一棵二叉树，节点数约 `2 × 1.618ⁿ`。
**每一层只减少 1，所以树高是 n，但节点数是指数级的。**

### 调用次数的精确公式

实测数据：`n=35` 时 29,860,703 次。

理论值：`T(n) = 2·F(n+1) - 1`。

```text
F(36) = 14930352
2 × 14930352 - 1 = 29860703   ← 和实测完全一致
```

**这个数字可以从实验输出直接验证**：`n=35` 的 F(n) 是 9227465，而
`2 × 14930352 - 1 = 29860703` 正好等于打印出的调用次数。

### 记忆化的一个陷阱

```c
#define FIB_UNSET UINT64_MAX      /* ✅ 用一个不可能出现的值 */

/* ❌ 用 0 当「未计算」标记是错的：fib(0) == 0 也是合法结果 */
```

如果 memo 初始化成 0，那么 `fib(0)` 每次都会被当成「没算过」重新计算，
递归退化成朴素版本。

### 矩阵快速幂的原理

```text
[F(n+1)  F(n)  ]   [1  1]^n
[F(n)    F(n-1)] = [1  0]

用二进制快速幂：n 的二进制有多少位，就只做多少次矩阵乘法。
n = 45 时只要约 log2(45) ≈ 6 次乘法。
```

### 溢出的精确边界

```text
========== 7. 溢出：uint64_t 能装到第几项？==========
  n      F(n)                  
  93     12200160415121876738  
  94     1293530146158671551      <-- 溢出了！
  检测到溢出起点: n = 94
```

`F(93) ≈ 1.22e19` 还在 `UINT64_MAX ≈ 1.8e19` 内，`F(94) ≈ 1.97e19` 超出。

**注意：无符号溢出是「有定义」的**（模 2⁶⁴ 回绕），所以程序不会崩，只会静默给出错误结果 —— **这比崩溃更危险**。

## 最佳实践

1. **斐波那契一律用迭代**（O(n) 时间，O(1) 空间），除非题目明确要求其他形式。
2. 记忆化的「未计算」标记值**绝不能和合法结果重合**。
3. **任何递归都要先数一数它的调用次数**，否则你不知道它是指数级的。
4. 用 `uint64_t` 时先算清楚最大能表示到第几项（Fibonacci 是 n ≤ 93）。
5. 矩阵快速幂在 n > 10⁹ 时才真正有意义；日常场景属于炫技。
