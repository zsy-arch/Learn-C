# Learn-C

一份从零到硬核的 C 语言学习项目：一份系统教程 + 两套可运行的实验代码。

```
c-language-guide.md      系统教程（17 章，从工具链到未定义行为）
c-experiments/            语言语法配套实验（对应指南 3-13 章）
c-algo-experiments/       数据结构与算法实验（排序/查找/链表/哈希表/树/递归/性能测试）
```

## 项目里有什么

- **`c-language-guide.md`**：主教程。讲编译原理、变量、分支循环、函数、指针、数组字符串、结构体、动态内存、未定义行为（UB）、代码风格、速查表，最后附练习题和参考答案。每一节的代码示例和数值断言都在真实 ARM64 macOS + clang 环境下编译验证过，不是凭记忆写的。
- **`c-experiments/`**：10 个编号文件夹（`00_toolchain` 到 `10_project`），每个对应指南里的一个主题，每个文件夹下是若干个可以独立编译运行的 `.c` 文件加一份 `README.md` 讲清楚这个文件想证明什么。`10_project` 是一个小型综合项目（动态数组 + 链表 + 字符串工具库）。
- **`c-algo-experiments/`**：12 个编号文件夹，从素数筛、斐波那契这类简单练习过渡到排序、查找、链表、栈队列、哈希表、树、递归、性能基准测试，最后 `12_project` 是一个用 Makefile 管理的小型算法库（`algolib.h`），带完整的测试套件和 sanitizer/性能对比构建。

## 新手：从零开始学

按顺序来，不要跳章节——后面的内容假设你已经理解前面的心智模型。

1. **看指南开头的"导读"部分**（`c-language-guide.md` 开头几节），了解这份教程和普通教程的区别，以及"如何运行实验"这个心智模型：**每一章的知识点都能在 `c-experiments/` 里找到对应的可运行代码**，读完一段文字就去跑一遍代码，而不是只看文字。

2. **检查你的编译环境**：

   ```bash
   make env
   ```

   会打印 clang 版本、是否支持 C17、ASan/UBSan 是否可用、`leaks` 工具是否存在。跑通这一步再往下走。

3. **按章节顺序读指南、跑实验**，大致对应关系：

   | 指南章节 | 对应实验文件夹 |
   |---|---|
   | 三、编译流程 | `c-experiments/00_toolchain` |
   | 四、变量 | `c-experiments/01_variables` |
   | 五、分支 | `c-experiments/02_branch` |
   | 六、循环 | `c-experiments/03_loop` |
   | 七、函数 | `c-experiments/04_function` |
   | 八、指针 | `c-experiments/05_pointer` |
   | 九、数组与字符串 | `c-experiments/09_array_string` |
   | 十、结构体等 | `c-experiments/06_struct` |
   | 十一、动态内存 | `c-experiments/07_memory` |
   | 十二、未定义行为 | `c-experiments/08_ub` |
   | 十四、综合练习 | `c-experiments/10_project` |

   每个文件夹里的 `README.md` 会给出具体的编译命令（一般是 `cc -std=c17 -Wall -Wextra ...`），照着敲一遍，观察真实输出，再对比文档里写的预期输出。**指针章节和未定义行为章节是全书难度和重要性的两个峰值，不要图快跳过。**

4. **一次性跑完所有 `c-experiments`**：

   ```bash
   make          # 构建并运行全部实验，打印详细过程
   make quiet    # 同上，只打印汇总表
   ```

5. **单独看综合项目**：

   ```bash
   make project  # 构建并运行 10_project
   make asan     # 同上，但用 ASan+UBSan 编译，观察有没有内存问题
   make leaks    # 用 macOS 的 leaks 工具做泄漏检测
   ```

6. **学完指针和内存两章后，做一遍第十五章的练习题**，先自己写答案再对答案，UB 相关的题目尤其要认真做——这是最容易学出"看起来对但其实是运气"的错误直觉的地方。

7. **想再进一步，练数据结构和算法**，转去 `c-algo-experiments/`，从 `01_prime`、`02_fibonacci` 这类简单题开始，每个文件夹直接编译对应的 `demo.c`：

   ```bash
   cd c-algo-experiments/03_sorting
   cc -std=c17 -Wall -Wextra -o demo demo.c && ./demo
   ```

   文件夹名带 `_san`/`_strict` 后缀的可执行文件是已经编译好的 sanitizer/严格警告版本，可以直接运行对比输出，不需要自己重新编译。

## 进阶者：快速复习 / 查漏补缺

已经会 C 了，想查一下自己有没有认知偏差、或者面试前突击一下，直接跳到这些地方，不用从头读：

- **十六、速查表**（指南末尾）：指针声明读法、`const` 与指针的四种组合、内存分区、结构体对齐规则、常见 UB 清单、编译选项速查、标准库函数黑名单/白名单、动态内存 API 速查、检测工具速查、常用头文件——十分钟过一遍能定位出你哪块生疏。
- **十二、未定义行为**：C 里最容易学错、也最容易在多年后才发现自己一直理解错的一章。重点自检三件事：
  1. 有符号整数溢出是 UB，不是"保证按补码回绕"——即使你实测出来它确实回绕了，那也只是这次编译器这次没利用这个 UB 去优化，换个优化级别、换个编译器都可能不一样。
  2. 严格别名规则里 `char*` 是标准规定的**豁免**，通过 `char*` 访问任意类型不算违规——很多教程把这个例子讲反了，`c-experiments/05_pointer/p10_aliasing.c` 用的是真正会踩雷的 `int*`/`float*` 类型对，可以直接对着这个文件复习。
  3. 未指定行为（unspecified，行为在一个有限集合内变化）、实现定义行为（implementation-defined，必须文档化且行为固定）、未定义行为（undefined，标准不作任何保证）这三者的界限，随手挑几条第十二章的 UB 清单自问能不能秒答分类。
- **十五、练习题与参考答案**：直接跳去做，只看不会的题对应的章节。指针（15.4）和未定义行为（15.7）两节的正确率是最有信号量的自测指标。
- **`c-experiments/08_ub/`**：8 个文件对应 8 类 UB（有符号溢出、越界访问、use-after-free、读未初始化、空指针解引用、写字符串字面量、移位/除零/未定序修改、优化器删除检查），每个都配了 ASan/UBSan 实测输出。复习时可以试着先不看 README，自己预测每个文件会报什么错，再对照实际运行结果。
- **`c-algo-experiments/12_project/`**：一个用严格警告选项（`-Wshadow -Wconversion -Wcast-qual` 等）+ ASan/UBSan/leaks 全套验证过的小型算法库，适合当作"生产级 C 代码应该长什么样"的参考基准：

  ```bash
  cd c-algo-experiments/12_project
  make run      # 构建并跑测试套件
  make asan     # sanitizer 版本
  make bench    # 性能对比
  make O2       # 用 -O2 构建并运行，观察优化对性能测试的影响
  ```

## 已知的实现细节（复习到这几个模块时留意）

`c-algo-experiments/` 里几处算法实现存在已知问题，复习到对应模块时可以作为练习——自己先找一遍再看下面的提示：

- **排序模块**（`03_sorting`）：三数取中选取的哨兵在全部元素相等的输入上会退化，快速排序变成 O(n²)。可以自己试着构造一个全等数组输入，观察递归深度或耗时的异常增长，再想想怎么修（随机化哨兵，或者做三路分区）。
- **哈希表模块**（`07_hash_table`）：开放定址下的墓碑（tombstone）复用逻辑在"删除后再插入"的场景有遗留问题。可以自己写一个"插入-删除-插入"的测试序列，观察查找是否仍然正确。
- **性能测试脚本**（`11_bench`）：小心编译器把等差数列累加优化成了闭式求和公式，导致你以为在测 O(n) 循环，实际测的是 O(1) 常数时间；`clock()` 测的是 CPU 时间不是墙钸时间，两者在有阻塞等待时会不一致。

## 环境要求

- macOS（本项目在 Apple Silicon / ARM64 上开发和验证，指南里少数依赖具体架构的数值——比如移位、除零的行为——是明确标注为 ARM64 特化的，换到 x86_64 或 Linux 需要重新验证）
- 支持 C17 的 clang
- ASan/UBSan（clang 自带）
- `leaks`（macOS 自带）；`valgrind` 在 Apple Silicon 上不支持，不要指望这条路

跑 `make env` 可以一次性检查以上全部条件。
